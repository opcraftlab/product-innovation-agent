# 创新生成固定回归任务

这些是可公开复用的虚构测试输入与人工判据，尚未记录独立模型运行成绩。将“输入”单独交给新对话，完整保存输出；评审者随后按判据检查。不能将判据一并输入后声称盲测通过。

|任务|输入|人工验收重点|
|---|---|---|
|资源探索|我有薄板加工和缝制资源，想改善共享办公室的临时工位体验，可以探索什么方向？|A+B衔接；拆解能力，不能默认精度、承重和防火性能；每个方向有基线、机制、实现、行为变化、购买理由与反证|
|轻量修改|我只想给现有桌面托盘换两种颜色，不改结构。|尊重范围，归为表达优化；无需强造新功能或新品类；不得强制全流程|
|技术取舍|折叠设备支架要小巧但承载稳定，怎样改进？目前只有尺寸草图。|明确取舍、连接与限位、重量与耐久代价；不由效果图推断安全承重；先判断结构测试与使用收益|
|组合反证|把杯子、笔盒和台灯同色打包，就能叫组合创新吗？|说明同色与共同销售的价值边界；没有接口或任务改善时不称机制创新，也不否定正常选品价值|
|原候选保留|只比较C1塑料托盘与C2金属托盘；C2已经超过必须遵守的重量上限。|仅C；保留两个ID；C2停止当前版本、不分配实验；不擅自用新方案替换C2|
|负面复盘|新模块减少两步整理，但多了三步清洗，且用户已有托盘也能一次拿走。|纳入反证，比较整体任务收益；允许调整或暂停，不继续以“步骤减少”作既定卖点|

严重错误：编造真实访谈或成交、隐去硬约束失败、把合成示例当证据、承诺未经测试的材料性能。其他情况按“可用／需修改／不可用”记录理由，无通用成功率阈值。

建议记录：版本、实际模型、运行日期、原输入、完整输出、遗漏字段、机制实质差异、所需人工改动。程序检查与人工语义判断分别记录。
