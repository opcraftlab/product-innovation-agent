# 方法组件与实现

本工具围绕三个任务组织18张方法卡：发现机会、形成产品方案、评审方向并设计实验。每张卡明确输入、动作、输出和常见误判；它们可以按任务组合，不要求每次顺序执行全部步骤。

## 保持一致的关系

市场定位、产品兑现与品牌认知必须服务同一项用户价值。市场定位说明目标人群、具体问题和替代方案；产品兑现说明功能、体验与实现能力；品牌认知说明用户应当理解和记住什么，以及为何相信。任一部分发生变化，都要回查另两部分是否仍然成立。

用户研究覆盖行为观察、使用情境、体验检查、参与反馈、购买与服务过程。实现能力与需求研究并行推进，既检查用户是否需要，也检查团队能否持续交付。

不同市场状态可对应不同进入方式：引入新的解决机制、提高现有体验标准、聚焦需求更明确的细分人群。这是候选路线，不是保证增长的公式。

## 方法卡与交付

|卡片|解决的问题|主要交付|
|---|---|---|
|M01 机会与资源选择|机会是否符合团队能力与资源|机会选择卡与放弃条件|
|M02 市场状态诊断|当前竞争状态适合怎样进入|进入路线与待证假设|
|M03 优先人群选择|先服务谁，如何接触|首批用户卡|
|M04 场景与进步|问题何时发生，改善什么|场景问题与改善指标|
|M05 替代方案地图|用户现在怎么解决，为什么换|替代方案与转换理由|
|M06 创新方向生成|有哪些实质不同的解决办法|可比较的候选方向|
|M07 能力与技术匹配|能否实现，缺什么能力|实现路线与关键试验|
|M08 产品承诺与体验|产品应带来什么可感知变化|产品定义与体验目标|
|M09 产品范围与组合|本轮做什么，暂不做什么|最小产品范围|
|M10 表达与承诺一致|定位、交付与品牌认知是否一致|用户价值—产品能力—表达—证据对应表|
|M11 全程购买与服务|从发现到使用哪里会中断|旅程与触点改进清单|
|M12 真实用户参与|反馈怎样改变产品决定|反馈、修改与再测试记录|
|M13 差异的持续性|优势依靠什么，何时失效|优势假设与失效条件|
|M14 最小实验|下一步怎样以较少成本获得信息|实验卡与执行优先级|
|M15 经济与交付闭环|收入能否覆盖完整交付成本|经济账与敏感项|
|M16 证据与反证|依据是否支持结论，有何相反信息|证据台账与冲突清单|
|M17 分阶段投入|当前应继续研究、调整还是停止|阶段建议及条件|
|M18 结果复盘与迁移|哪些方法可复用，哪些条件要重查|复盘记录与迁移条件|

## 程序检查与人工判断

程序检查输入结构、引用ID、证据标记、适用范围、硬约束和实验预算；这些检查不能代替对事实真实性、方法适配和方案质量的判断。提示词与方法卡属于运行指令，本项目没有训练或微调模型。

团队决定资源投入并执行实验，再把实际结果作为新证据输入。方法卡提供操作框架，具体指标、样本与停止条件需要根据项目确定。
