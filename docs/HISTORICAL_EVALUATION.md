# 历史案例重演：输入、输出与后续事实分开

用途是检查方法产生的方向与后来决策的结构对应关系，发现遗漏。它不等于预测成功率。模型可能已从训练或当前上下文知道案例；去品牌并不能保证盲测。

## 推荐流程

1. 写明案例选择、决策截止日、后续对照节点、执行模型和方式。同时保留失败案例，不只挑成功品牌。
2. 拆分资料：节点时已可得的输入、后述重建背景、后续结果、应排除项。事件发生日期不等于资料可获得日期。
3. 对每个输入保留来源及可获得日期，先审查台账。缺少同期记录时明确用重建模式，不能宣称严格时间隔离。
4. 在运行前固定特征评分标准、部分分规则、分母和版本。已在输入明确给出的答案不能算作新发现。
5. 用concept自由生成候选，再用validation决定先验证顺序。不要先把成功方案作为候选再声称Agent发现它。无需机械执行全部三个Agent。
6. 保存导出的完整prompt、输入摘要、原始输出、执行方式、模型版本/未知项、尝试次数和时间；不满意的结果也保留。
7. 逐个方案单独计分。分别报告优先验证方案对应度与单个候选中的最高对应度，不能拼接多个方案的优点。
8. 输出中的每个得分要引用实际字段并解释。严格符合项与部分符合项分列；自评要标注。
9. 加入普通提示词基线、失败案例、独立评审和重复运行后，才讨论方法增益与稳定性。真实商业效果仍需要真实实验。

## 日期审查工具

从源码仓库运行：

```bash
python scripts/check_historical_packet.py packet.json
python scripts/check_historical_packet.py packet.json --allow-reconstruction
```

仅在接受后述重建局限时使用第二条。台账示例（虚构示意）：

```json
{
  "cutoff": "2015-12-31",
  "items": [{
    "id": "I1",
    "role": "input",
    "basis": "contemporaneous",
    "statement": "此前访谈记录中的一条限定观察",
    "source": "团队实际保存的访谈记录路径",
    "source_available_at": "2015-11-20",
    "event_date": "2015-11-19"
  }]
}
```

role为input、heldout、excluded；basis为contemporaneous或retrospective_reconstruction。日期未知写null，不能猜造日期。后述资料即使描述旧事件，也不自动成为当时可得证据。

工具检查所填日期、重复ID、来源字段、输入是否含未来事件。它**不会**核实来源真实性、从自然语言提取日期、自动删除prompt内容，或消除模型记忆；尚未整合为task子命令的自动前置门槛。公开工具只提供通用审查能力，实际项目台账保留在使用者自己的工作区。

## 如何报告结果

自行开展评测时，注明输入截止日、材料可得日期、模型是否可能见过后续结果、基线、独立评审及重复运行情况。缺少这些条件时，结果只能用来发现方法遗漏，不应报告为预测准确率。公开示例采用虚构数据；本仓库未提供可用于证明商业效果的独立评测数据集。
